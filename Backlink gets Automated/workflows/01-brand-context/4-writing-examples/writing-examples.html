Writing Examples — show, don't tell

One command picks 5 of the company's best real, published articles, scores each against brand-voice.md, and rebuilds the full text with a pillar-grounded note on why it works. This is the "show" companion to brand-voice.md's "tell." Here's exactly how it runs, script by script.

01The one idea

Take every real published article the company already has on disk, rank the best ones by traffic, judge which ones truly sound like the brand, and rebuild the top 5 in full with a note on why each one works. A writer imitates these instead of guessing.

📚

Pool the articles

Read the catalogue, keep only editorial blog types, order them by traffic. No fetching — everything is already saved.

⚖️

Score the voice

One AI call per article scores it out of 10 against brand-voice.md only — not "good writing" in general.

🔁

Loop until 5 pass

Most old content fails its own brand. Pull another batch and re-score until 5 on-voice articles survive.

🧱

Rebuild in full

Paste each survivor's full text verbatim, add its metadata and 2–3 pillar-grounded reasons.

The one rule that governs everything

Every example is a real, published article that genuinely embodies brand-voice.md — pasted in full and verbatim, with a "What Makes It Great" grounded in named brand-voice pillars, never generic praise.

  • Voice fit is judged in exactly one place: the Step-2 scorer rates each article out of 10 against brand-voice.md and nothing else. An off-voice article gets no annotation and is dropped.
  • Every "What Makes It Great" reason must name a pillar. A reason that cites no pillar is a vibe, not evidence — it does not belong.

02The words you need first

Five terms this engine leans on. Each is defined once here, then used exactly.

brand-voice pillar — a named characteristic from brand-voice.md, the voice standard built by an earlier builder. Real Testlify pillars include "Show the Number," "Skills Beat Resumes," and "The Hiring Coach." Every annotation reason must name one.
on-voice / off-voice — the scorer's verdict. On-voice means the article demonstrably hits the pillars, so it can be kept and annotated. Off-voice means it reads like generic content, so it is dropped with no annotation.
verbatim — pasted word-for-word, not paraphrased or trimmed. The full article body goes into the file exactly as published (bar a few trailing "Book a demo" chrome lines the script strips).
format — the shape of the article (comparison, listicle, how-to, definitional…), inferred from its URL slug alone, before any body is read. Used to keep the final 5 varied.
the catalogue — content-database.csv, the site-wide inventory built by Layer 00. It holds every page's full text, title, type, and traffic on disk, so this engine never has to fetch a live URL.

03The architecture

A small scripted pipeline: one settings file, one AI caller, one prompt file, one orchestrator that runs the three steps in order and is resumable.

FileRole
config.py The one settings hub. Every path derives from one repo-root anchor; the company is a single COMPANY env var. Holds the tunables:
  • KEEP=5 — final count.
  • BATCH=8 — articles scored per round.
  • MAX_ROUNDS=4 — scoring rounds before it gives up loudly.
  • WORKERS=4 — parallel AI calls.
  • BODY_CHAR_CAP=16000 — chars of each article shown to the scorer.
llm.py The one AI caller. Runs each prompt through a headless CLI — Claude or Codex (set by LLM_PROVIDER, default claude), no API key. Notable behaviour:
  • call_json() pulls JSON back out of the model's reply, tolerating code fences.
  • Retries a briefly-failing CLI up to 4 times with growing backoff; nudges once on unparseable JSON.
  • Stops the whole run on a credit/auth failure instead of hammering the CLI.
prompts/score-article.md The single scoring prompt, kept out of the code. Fills {{BRAND}} · {{URL}} · {{KEYWORD}} · {{VOICE}} · {{BODY}} and asks for score + verdict + annotation as JSON.
run_writing_examples.py The one entry command. Runs the three steps in order, caches scores to scored.json so a re-run resumes, and writes the deliverable. --redo forces a fresh score.

Where the work splits: code vs the AI

⚙️

The code does the structure

Deterministic, free, repeatable
  • Pool + editorial filter + traffic order
  • Format tag from the URL slug
  • Batch selection with format diversity
  • Rank, keep top 5, count words, strip CTA lines, assemble the file
Never decides whether an article is on-voice — that judgment is not code's to make.
🧠

The AI does the judgment

Claude or Codex, one call per article
  • Reads the article body + brand-voice.md
  • Scores it out of 10 on voice alone
  • Returns on-voice / off-voice + why
  • Writes the pillar-grounded "What Makes It Great"
The only judge of voice fit — decided once, in one place, per article.

04The full pipeline

Three steps plus a gate. The code owns selection and assembly; the AI owns the one judgment in the middle. Everything runs free on the local CLI.

1

Classify & select code free

Build the candidate pool from what's already on disk, then pick a diverse batch to score.

  • Read the catalogue and keep only rows that are fully scraped and in the target language content-database.csv
  • Filter to editorial types (post, hr-glossary, job-description, interviews…) from Layer 01's type-roles.json — drops product, pricing, glossary-index, and tool pages
  • Walk the pool in traffic order and take Traffic + primary keyword as-is top-pages.csv
  • Tag each article's format from its URL slug, then pick BATCH=8 round-robin across formats, highest-traffic first
  • ↓ 05 — how the format tag works
2

Score & annotate Claude / Codex free

One AI call per article, four running in parallel, judged only against the brand voice.

  • Fill the prompt with the article body + brand-voice.md and ask for JSON: score, verdict, why, annotation, exact H1 prompts/score-article.md
  • Run the batch across WORKERS=4 threads; cache every result so a crash resumes scored.json
  • If fewer than 5 on-voice so far, pull the next batch and score again — up to MAX_ROUNDS=4 rounds
  • ↓ 06 — the scoring judgment, with real numbers
3

Assemble code free

Pure assembly — it only arranges what earlier steps produced; it invents nothing.

  • Sort the on-voice survivors by score, keep the top KEEP=5
  • For each: write URL, primary keyword, format, voice score, a code-counted word count, the annotation bullets, then the full body verbatim
  • Strip trailing chrome lines (Try for free / Book a demo / Sign up / View plans) so only real article text remains
  • Write it in place 01-brand-context/writing-examples.md — ↓ 07 — a real assembled block
✓

Gate guardrail

Two automatic checks flag trouble instead of silently shipping a weak set.

  • If the 5 span fewer than 3 formats, insert a ⚑ HUMAN DECISION line at the top of the file for review
  • If fewer than 5 on-voice ever survive, ship what there is but say so loudly in the run log
  • The pillar-naming rule itself is enforced inside the prompt, not by a post-check

05Format, from the URL alone

Before any article is read, the code tags its format from the URL slug so the final 5 stay varied. This is a fixed list of four slug patterns plus a catch-all — the exact rules that live in the script.

Slug containsFormatExample URL
what- · definition · types-ofDefinitional / pillar/what-is-dei/
top-N · -questions · N-waysListicle/top-10-aptitude-assessment-questions…/
how-to · -process · -stepsStep-by-step how-to/walmart-hiring-process/
-vs- · alternativesComparison/white-collar-vs-blue-collar-jobs/
none of the aboveThought-leadership / otherthe catch-all fallback
One honest gotcha

The matcher is deliberately coarse. Any slug containing -process lands in "Step-by-step how-to" — so in the real Testlify run both Walmart hiring process and Business process outsourcing were tagged how-to, even though a human might have called them a case study and a definition. The tag is a cheap diversity lever, not a precise taxonomy.

06The scoring judgment

This is where the intelligence lives. One prompt reads one article plus the whole brand-voice standard and returns a single verdict — and only the on-voice ones earn an annotation.

What the AI is handed, and what it returns

  • Given: the article body (first 16,000 chars), the full brand-voice.md, plus the URL and primary keyword marked "use as given, do not re-derive."
  • Hard stop in the prompt: score only against brand-voice.md — not against generic "good writing" or the model's own taste.
  • Returns JSON: score 0–10 · verdict on/off-voice · verdict_why · what_makes_it_great (2–3 pillar-named reasons, empty if off-voice) · h1 the exact headline.

Why real articles get dropped

The verdict names the pillars an article misses. Two real off-voice reasons from the run:

  • /hr-glossary/generation-x/ — 3/10: "Third-person encyclopedia prose with zero exact numbers, unnamed 'HBR/SHRM research' citations, and no runnable next step — it fails Show the Number and The Hiring Coach almost entirely."
  • /maintenance-technician-interview-questions…/ — 4/10: "Delivers the coach-style 'Look for:' lists the brand prescribes, but opens with exact banned fluff ('In today's rapidly evolving industrial landscape') and cites unnamed 'recent research'."
The lesson the recipe insists on

Don't expect the first batch to yield 5. Most old content is off its own brand: score a batch, keep the winners, pull another batch, repeat until 5 survive. The loop is built for exactly this.

What changed from the old design

The voice score is no longer a hidden working value — the assembled file now prints **Voice Score**: X/10 and **Format** on each example, so the reviewer can see at a glance how strong each pick was.
