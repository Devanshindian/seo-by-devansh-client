Voices — who wrote it

Capture the real bylines content is published under: one default company byline, one founder voice, and any other named authors, each with the credential detail an author box needs. A script drops the questionnaire; the team fills it with real people; the answers become a preserved seed the write phase reads. Here's exactly how it works, file by file.

01The one idea

Every article needs a named author for its author box (an E-E-A-T lever). This builder settles, once per company, who those real authors are and which one each piece gets. It is a questionnaire, not an AI writer.

📋

Drop the skeleton

A tiny script writes a blank questionnaire into the company folder, only if one isn't there yet.

🗣️

The team fills it

Real bylines only: the company team byline, the founder, any named authors. Never machine-drafted.

🔒

Seed is preserved

Once answered, the file is a seed. A rerun reuses it and never overwrites the real answers.

🎯

Downstream routes it

Later, the research bundler reads this file and picks the one byline each article carries.

The one rule that governs everything

Every byline is a real person or the real company team — never invented.

  • Default to the company-wide byline (e.g. "Testlify Team"), not an individual writer.
  • Use a named individual only where it genuinely fits: founder/CEO for strategy and vision, or when a client explicitly asks.
  • The byline is not the reader persona. The persona is who the article is written to; the byline is who wrote it. Different files, kept separate.
  • E-E-A-T comes from real credentials, cited data, and the bio — never a fabricated personal story.

02The words you need first

Six terms this page leans on. Each is defined once here, then reused with the same wording.

Byline — the author name a published article carries, plus the credential line beside it (name · role · author-page or email). It is what renders in the article's author box.
Reader persona — who the article is written to (the audience's depth and angle). A different builder owns it. The byline is who wrote it; the two are never mixed.
E-E-A-T — Experience, Expertise, Authoritativeness, Trustworthiness: Google's signal that real, credentialed people stand behind the content. A true author with a real bio is one lever for it.
Auto-route — three fixed rules, applied in order, that decide which byline a given article gets with no one being asked. Founder topics go to the founder; everything else goes to the team byline.
Seed — a human-filled file that later steps read but never regenerate. Once the team answers the questionnaire, voices.md is a seed: a rerun of the builder reuses it and leaves it untouched.
First-hand markers — the honest experience phrases a byline may use ("Across the teams we work with…"). For the company byline they are collective ("we"), never a fabricated individual memory.

05Byline anatomy — the fields a byline carries

Every byline table holds the same fields, so the write phase can render an author box from any of them. These are the fields the default company byline fills.

Display name
The author name shown on the article. For the default, the team name, not a person.
Author page
A live author-page URL, verified to load — the link the byline points at.
Tone
How this voice sounds, in one line (e.g. data-led, practitioner, clear).
Person
The grammatical person rules: second person for how-tos, first-person-plural for shared-experience markers.
First-hand markers
The honest experience phrases this voice may use — collective for the team byline, never an invented personal memory.
Bio (E-E-A-T)
A one-line credential bio: what the author covers and the real grounding behind it.
Byline line
The assembled attribution string: Name | Company | author-page.

06Auto-route rules — applied in order

No one is asked. These three rules, in this order, decide the byline for any article. A named individual is used only when explicitly requested. The rows below are Testlify's real, filled rules.

PriorityIf the article is…Byline
1leadership / vision / CEO / strategy-at-scale / future-of — or a press release / white paper / PR pitchAbhishek Shah — founder voice
2everything elseTestlify Team — the company-wide default
3a piece where the user explicitly asks for a named authorthat named individual (e.g. Yashika, Aparna) — never automatic
Never auto-route to a named individual

Even if a recruiter-focused how-to looks perfect for Yashika, it still goes to the default team byline unless the client specifically says "use Yashika for this." Named authors are opt-in, not automatic — that is exactly why rule 2 catches "everything else" before any individual is reached.

Where this sits in the bigger machine

This is builder 6 of Layer 01 (Brand Context). Its output is consumed downstream, in Layer 03's research-conductor:

  • Upstream: nothing depends on it. The team's answers are the input; it reads company.json only for the brand name.
  • Downstream: the research bundler 14-research-conductor/scripts/bundle.py reads voices.md and, via the prompt pick-author.md, applies these auto-route rules to pick one byline per article. That pick is the single AI step that touches this file — it runs on Claude or Codex, no API key.
  • What it renders: the bundle's cover sheet gets an "Author byline" line — the chosen display name plus its byline line — and points the writer back to voices.md for the full voice detail.
