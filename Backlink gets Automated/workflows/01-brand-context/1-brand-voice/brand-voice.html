Brand Context · Layer 01 — Builder 1 of 7

Brand Voice — the writing standard every later builder reads

Reads the company's own cornerstone pages and turns them into a complete voice document — pillars, tone, messaging, style rules, audience. One scripted command runs it end to end; every line traces to a real page, nothing invented. Here's exactly how it works, script by script.

The idea The words Architecture Pipeline Evidence row Filling the doc Quality gate Output & fit

01The one idea

Learn how a company writes by reading what it already published, not by guessing. The engine picks the pages worth learning from, reduces each to a small evidence row, then assembles those rows into one voice document — and grades it for depth before it ships.

🗂️

Shortlist the voice pages

From the site catalogue, pick 20–40 pages worth learning the brand voice from: the top-traffic winners plus the commercial/positioning pages traffic alone misses.

🔎

Read each into a row

One AI read per page pulls six fixed fields — tone, positioning, audience, a quote, style/CTA, and any company-specific theme. This is the evidence table.

🧱

Assemble the document

Fill each section of the fixed schema by pulling its mapped column across all rows. Pure assembly — arrange the evidence, invent nothing.

✅

Grade it, then loop

An AI judge checks completeness, depth and specificity against the bar. Fail sends redo notes back to assembly, up to three rounds.

The one rule that governs everything Every cell in brand-voice.md must trace to a real page we read — a trait observed in the prose, a verbatim excerpt, or a stated brand fact. Nothing is invented.
  • If the pages don't evidence a section, it is flagged for the human (> ⚑ HUMAN DECISION:) — never fabricated to fill space.
  • A filled Castos example (a podcast host, in the recipe's Appendix B) is a depth and completeness bar only. Borrowing any of its wording, pillars, or examples is an automatic fail at the gate.

02The words you need first

A few terms carry the whole page. Each is defined once here, then used the same way throughout.

Cornerstone page — a page that carries the brand's real voice: the homepage, pricing, "why us", top blog posts, product pages. The shortlist step picks these; the writing is learned only from them.
Evidence row — one page reduced to six fixed fields (tone, positioning, audience, a quote, style/CTA, a company-specific theme). The whole document is built from these rows and nothing else.
Pure assembly — the writing step only arranges the evidence it was handed. If a line can't be traced back to an evidence row (or a stated brand fact), it doesn't belong in the document.
Pillar — a named theme in how the brand communicates, a characteristic that recurs across many pages (e.g. "Confident, Proof-Backed"). The name is decided last, after clustering the evidence — never picked first and forced to fit.
Thin page — a saved page under 150 words, usually a JavaScript-heavy homepage or pricing page the catalogue stripped. The read step falls back to the catalogue's full content for the same URL; a page thin in both is recorded as thin, not guessed at.
Quality gate — an AI judge that grades the draft for completeness, depth and specificity against the recipe's bar, and returns a pass/fail per section plus redo notes. It loops back into assembly on a fail.
Human gate — the one manual step: review the change with git diff and confirm the drafted one-liner + niche into the company record. The engine writes the file in place; a person approves it.
Headless CLI — the way every AI call runs: a local Claude Code or Codex command, text in and text out. No API key, no server, so a run costs nothing. Parallel calls act as our "sub-agents".

03The architecture — one scripted twin of the recipe

The recipe (brand-voice.workflow.md) is the human-readable WHAT/HOW. Its runnable twin (run_brand_voice.py) executes the same steps in order, is resumable, and reads the schema straight from the recipe so the recipe stays the single source of truth.

FileWhat it does
run_brand_voice.pyThe orchestrator. Runs the steps in order and nothing else. Resumable — reuses each step's saved output unless a redo flag forces it. Prints == Step N == as it goes.
config.pyEvery path + tunable from one anchor. Company is one setting (COMPANY=<slug>); it reads the company record for brand, niche and domain. Holds the knobs:
  • page band 20–40 · workers 4 · thin cutoff 150 words
  • gate rounds 3 · body cap 14,000 chars per page
llm.pyThe one AI caller. Runs each prompt on the headless CLI — Claude Code or Codex, no key. call_json parses JSON back (retries on a bad parse); call_text returns a whole document. Backs off on a busy CLI; stops the run on a credit/auth failure.
prompts/*.mdOne file per AI call — pick-pages.md, extract-evidence.md, assemble-voice.md, quality-gate.md, draft-oneliner.md. Kept out of the code, diffable, single-sourced.
shortlist.py · read_pages.py · assemble.py · quality_gate.pyOne script per step. Each reads its input file, does the work, writes a named output the next step reads.

Four steps, each writing a named file the next reads: page-shortlist.md → evidence.json → brand-voice.md → the gate verdict. Run it with COMPANY=<slug> python3 scripts/run_brand_voice.py.

05The evidence row — the atom everything is built from

Every page becomes one row of six fields. The read prompt is strict: draw only from this page, quote verbatim, and leave a field empty if the page doesn't evidence it — a blank is information, not something to pad.

voice_tone
How it sounds (warm / blunt / confident / formal…) plus one short cue phrase copied from the text.
positioning
What the company says it is / stands for / promises on this page.
audience_pain
Who the page speaks to and the pain it names.
quotable
1–2 real lines worth using as a "this is our voice" example — copied exactly.
style_format_cta
Sentence feel, headline shape, list use, and the exact CTA button text.
company_dimension
The one open field — filled only if a distinct recurring theme the others miss shows up (e.g. an assessment library, anti-cheating); else empty.

What one row looks like

The read step returns JSON per page; laid out as a table it reads like this. Illustrative format — the field values here show the shape, not a verbatim saved run:

Pagevoice_tonepositioningaudience_painquotablestyle_format_cta
002-hire-the-best
testlify.com/		 Confident, direct, second-person; no hype "Hire the best, not just hire" — quality-of-hire over speed Hiring teams afraid of a bad hire "Don't just hire — hire the best." Short punchy H1s; colon-led lead-ins; CTA: "Try for Free", "Book a Demo"

Blank cells are fine. If a page doesn't speak to a column, the field is empty — that tells you the page doesn't address that topic. Padding it with a guess would corrupt the evidence the whole document rests on. A thin page is tagged [THIN PAGE — weigh lightly] when its rows reach the assembler.

06Filling the document — assembly by mapped column

Each section of brand-voice.md is written by pulling one evidence field across all ~30 rows and writing from that alone. The mapping isn't just declared — it's the instruction the assembler acts on.

What a filled pillar looks like

Illustrative — the shape of one pillar, using the four required sub-fields:

Example pillar — Confident, Proof-Backed
What it meansClaims land with real numbers, not adjectives. Every assertion is grounded in a stat, an outcome, or a named fact.
How it soundsDirect, second-person, specific — like a hiring expert talking to a peer, not a marketer talking at a prospect.
Example"Companies that switch to skills-based hiring reduce time-to-hire by 55% and cut hiring costs by 72%."
AvoidWorld-class, seamless, revolutionary — any adjective asserting quality without evidence. (A testable check, not a sentiment.)

Deciding the name first forces the evidence to fit a label instead of the other way round.

07The quality gate — depth without copying

The gate checks the draft is as complete and deep as the reference bar, and as specific to this company as it must be — without having borrowed a word of the reference. It's an AI judge for the judgment plus a code check for the one thing a judge can miss.

The six things the judge checks

CheckWhat fails it
CompletenessA required header missing or empty, or any [BRACKET] placeholder left
DepthA section noticeably thinner than its required counts (e.g. fewer than 3 pillars, no tone variation per type)
SpecificityVague filler where the company's real numbers, product names or CTA text should be
Falsifiable rulesAn "Avoid" line that's a sentiment ("don't oversell") instead of a check a reviewer can run
Careful fairness languageauto-fail "bias-free", "eliminates bias", or any absolute fairness claim about the product — indefensible, and every article would inherit it
Observed, not inventedExamples that read as plausible LLM filler rather than sourced site copy; an unflagged numeric rule with no evidence

A > ⚑ HUMAN DECISION: flag is treated as honesty, not a failure — the judge never fails a section for flagging a genuine gap.

The code adds one deterministic check

After the judge returns, quality_gate.py scans for leftover uppercase-bracket placeholders. Any hit forces overall_pass = false and appends the exact tokens to the redo notes — a check that's cheap in code and easy for a judge to overlook.

The loop

FAIL
gate round n — redo notes written
→
re-assemble
Step 2 re-runs with the notes; up to 3 rounds

Each round writes gate-round-<n>.json so the history is legible. If it still fails after three rounds, the draft ships with its verdict attached and the call moves to the human gate — the loop never hides a failing document, it surfaces it.

The reference is a bar, never a sourceThe recipe carries a fully-filled example for Castos (a podcast host) purely to show how thorough the document should be. If any wording, pillar, message or example is borrowed from it, that section is an automatic fail and gets rebuilt from the company's own pages. We match how thorough it is, never what it says.
