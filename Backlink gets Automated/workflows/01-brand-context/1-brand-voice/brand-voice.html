Brand Voice — the writing standard every piece follows

Reads the company's own cornerstone pages and turns them into a complete voice document — pillars, tone, messaging, style rules, audience. Every line traces to a real page, nothing invented.

Concept Output Steps What's inside

01The one rule

Every cell in brand-voice.md must trace to a real page — either a trait observed in the prose or a verbatim excerpt. Nothing is invented.

If the company's pages don't evidence a section, it gets flagged for the human — never fabricated. A Castos reference example exists as a depth and completeness bar only. It is never copied from.

Input ~30 cornerstone pages already saved as clean markdown files from the brand brain step. Plus the page shortlist with their live URLs in case any saved file reads thin.

02What this produces

projects/[company]/content-machine/brand-context/brand-voice.md

The complete voice document. Every section filled, every claim backed by a page. This is what every later write, rewrite, and optimise pass reads first.

03Three steps

1

Read each page and extract one evidence row per page

Each of the ~30 pages gets its own AI agent that reads the full page and fills in five fixed fields. All agents run in parallel. The result is an evidence table — one row per page — that becomes the raw material for everything that follows. Nothing in the final document is invented; it all comes from these rows.

What the evidence table looks like

Five columns, one row per page. Here is a real example row from Testlify's homepage:

Blank cells are fine — if a page doesn't speak to a particular column, leave it empty. A blank is useful data (this page doesn't address that topic); padding it with guesses would corrupt the evidence.

2

Fill the brand voice document — section by section from the table

The brand-voice document has fixed sections: pillars, tone guidelines, messaging, value propositions, writing style, formatting, voice examples, and audience understanding. Each section is built by pulling a specific column from all ~30 rows and writing from that evidence alone. Think of it as assembly, not writing from scratch.

What "pillars" means

A pillar is a named theme in how the brand communicates — a recurring characteristic that shows up across multiple pages. For example, after reading 30 pages you might notice that the brand consistently writes in a confident, proof-backed tone and never uses adjectives without data to back them up. That pattern gets named "Confident, Proof-Backed" and becomes one pillar.

The way to find pillars is to read the Voice & tone and Positioning columns across all rows, group the ones that share a characteristic, and then name each group. The name comes last — not first. If you decide the name before reading the evidence, you end up forcing the evidence to fit a label instead of letting the label emerge from what's actually there. Most brands have 3–5 pillars.

If after reading all 30 pages a section still doesn't have enough real evidence to fill it properly, flag it for the client. Don't fill the gap with generic statements — a brand voice document written from guesswork defeats its own purpose.

3

Quality check

Every section in the template must be filled with no placeholder text left. The document should have 3–5 pillars each with all four sub-fields (see the example in the next section), tone described for each content type, messaging for each real customer segment, real CTAs and product names throughout. Anything thin or vague goes back to Step 2 to be rebuilt from the evidence.
