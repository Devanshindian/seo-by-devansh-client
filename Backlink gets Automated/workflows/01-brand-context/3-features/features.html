Content Machine · Stage 0 — Brand Context

Features — the product facts every writer needs

Reads every commercial page the company has, extracts the real facts into eight categories, then maps those categories into the sections of features.md. Writers reference this before mentioning the product in any content.

Concept Output Steps Category → Section Real example

01The one rule

Every fact in features.md comes from a real page. Nothing is invented.

  • If a fact isn't on any page, it gets flagged for the client — not made up
  • The only thing that gets written (not extracted) is the Conversion Angle — a one-line pitch for each feature explaining why the reader should care. Even that must be grounded in a real page fact and must match the brand voice.
Inputs content-database.csv — all page URLs (to discover which are commercial) and their full stored body text (to extract facts from). Plus brand-voice.md so Conversion Angle wording sounds like the brand.

02What this produces

projects/[company]/content-machine/brand-context/features.md

The complete product reference: value propositions, full feature set, integrations, competitive differentiators by named competitor, use cases by segment, pricing tiers, conversion messaging, and objection Q&As — all from real pages.

03Four steps

1

Discover the commercial pages — from URLs only, no reading

  • Pull all URLs from the content database
  • Classify each from its slug alone — no fetching or body reading at this stage
  • Keep: homepage, pricing, product/feature pages, integrations, competitor comparisons
  • Drop: blogs, guides, glossaries, templates, tools, company-info pages, non-English duplicates
2

Extract facts from every commercial page — eight fixed categories

Pages are split across 7–10 AI agents running in parallel. Each agent reads the full stored body text of its assigned pages and pulls out facts under exactly eight categories:

  • Features — every product capability and what it does
  • Integrations — every named tool or platform it connects with
  • Pricing — plan names, what each includes, the pricing model, trials, guarantees
  • Competitive — advantages over named competitors (only when the page names one)
  • Social proof — real customer numbers, outcome stats, ratings, certifications, awards
  • Audience/segments — who the page says the product is for, and the pains it names
  • CTAs — the exact call-to-action button text on the page
  • FAQ — any question and answer pairs on the page, verbatim

Pricing and integrations pages are fetched from the live website rather than the stored copy — these use dynamic tables that often don't save correctly. All extractions combine into one facts pool, one block per page.

3

Fill features.md — each category maps to a section

Each of the eight extraction categories maps directly to one or more sections in features.md. For each section, gather that category from every page block in the pool, consolidate duplicates into one canonical line (keeping the most specific version — the one with real numbers or the fullest list), and fill the section. See the mapping table below.

  • Every fact that was extracted must end up somewhere in the document — nothing dropped quietly
  • A top feature appears twice by design: once in Core Value Propositions (the 5–10 strongest, each with a pitch line) and again in Technical Features (the full list grouped into categories)
4

Quality gate

  • Every section is filled — no placeholders
  • Every fact from the pool appears somewhere in the document
  • Real numbers, integration names, competitor names, and prices are spot-checked against the pool
  • Conversion angles sound like the brand
  • Anything missing or unverifiable loops back to Steps 1 or 2

04How extracted categories become sections

Each category pulled in Step 2 has a direct home in features.md. This is the mapping.
