Content Machine · Reference Standard

Avoid AI Writing — strip the AI-isms before anything ships

A writing-quality standard, not a verdict. It flags the word choices, sentence shapes, and formatting that show up far more often in machine-generated text, then rewrites them so the piece reads like a person wrote it. In the content machine it runs as the final pass before publish. Here is exactly what it looks for, how it decides, and how a pass runs.

01The one idea

Some words, sentence shapes, and formatting habits appear 5–20× more often in LLM output than in human writing. This standard finds them and removes them — so the text reads human, not like a generic vendor. It is a quality filter, used as a signal, never as an accusation.

🔍

Audit

Read the draft and flag every AI-ism, quoting the exact offending text.

✍️

Rewrite

Replace each flagged span with a direct, concrete, human phrasing. Change only what the rules require.

📈

Three tiers

Words are ranked by how strongly they signal AI — always-flag, flag-in-clusters, flag-by-density — so fine-in-isolation words don't get over-flagged.

⚖️

Honest signal

The same shapes appear in second-language and deadline writing. Treat a hit as a signal, not proof.

The one rule that governs everything Signals, not proof. These patterns are statistically more common in AI text, but humans on autopilot — under deadline, in a new genre, or in a second language — produce the same shapes. Audits of commercial AI detectors found false-positive rates above 60% on non-native English writers (Liang et al., Stanford, Patterns 2023) and misclassification above 70% on open-source detectors (Jabarian & Imas, BFI 2025). Adversarial paraphrase cut detection accuracy by roughly 88% across every method tested (arXiv:2506.07001, 2025). So use it to clean writing and to sense whether a piece reads as machine-made — never as the sole basis for a consequential call (integrity, hiring, publication).

02The words you need first

Load-bearing terms, each defined once. Everything below reuses these exactly.

AI-ism — a word, sentence shape, or formatting habit that shows up far more in machine-generated text than in human writing (e.g. "delve into", the em dash, "it's not X, it's Y"). The unit this standard hunts and removes.
The three word tiers — how reliably a word signals AI.
  • Tier 1 — always flag. Appears 5–20× more in AI text. Replace on sight (delve, leverage, robust, seamless).
  • Tier 2 — flag in clusters. Fine alone; two or more in one paragraph is the tell (harness, foster, streamline, elevate).
  • Tier 3 — flag by density. Normal words AI overuses; only flag when they saturate the text (≈3%+): significant, innovative, effective.
Severity P0 / P1 / P2 — how urgent a fix is, for triaging a large document.
  • P0 — credibility killers, fix immediately (cutoff disclaimers, chatbot artifacts, vague attributions).
  • P1 — obvious AI smell, fix before publishing (word-list hits, template phrases, bold overuse).
  • P2 — stylistic polish, fix when time allows (rule of three, uniform paragraphs).
Mode — what the pass actually does: rewrite (flag + fix, the default), detect (flag only, no edits), or edit (change a named file in place). ↓ §03
Context profile vs voice profile — two independent dials. Context (linkedin, blog, technical-blog, investor-email, docs, casual) sets how strict to be for the audience. Voice (casual, professional, technical, warm, blunt) sets how the prose should sound. You can write blunt for a blog or warm for docs. ↓ §08
Type-token ratio (TTR) — distinct words divided by total words; a rough read on vocabulary range. Human prose over ~200 words usually lands 0.50–0.65; AI can drift under 0.40 when it loops on a small vocabulary. Low TTR is a second look, not proof.
Copula avoidance — dodging plain "is" / "has" for fancier verbs ("serves as", "features", "boasts", "presents"). Reads like a press release. Default back to "is" / "has" unless the stronger verb truly adds meaning.

03Three modes, two dials

One skill, three jobs. Pick the mode by what the writer wants done to the text; then optionally set the two dials — context (how strict) and voice (how it sounds).

✍️

rewrite default

Flag every AI-ism and return a clean version. Output has four parts:

  • issues found (each quoted)
  • the rewritten text
  • a diff summary of what changed
  • a second-pass audit that catches survivors
🔍

detect

Flag only, no edits. Use when the writer wants to decide the fixes, the patterns may be intentional, or the text must not be altered. Output:

  • issues found, grouped P0 / P1 / P2
  • an assessment: clear problem vs judgment call
📝

edit

Change a named file in place with minimal, targeted edits. Rules:

  • leave already-human passages untouched
  • never touch quotes, code, or others' attributed text — flag those instead
  • re-read after, confirm patterns resolved

How the two dials compose

Voice sets the target; context sets how hard to enforce it. A voice target always applies, even where a context profile would skip that category (technical voice still prefers plain "is" in a casual context). Where the two dials govern the same rule and disagree, resolve toward the stricter of the two — a warm voice on docs still gets no decorative tables.

Iterate to convergence (optional) Rewrite mode already runs one corrective second pass — that built-in pass is pass 2. Asking to "keep going" repeats the audit→rewrite cycle, capped at N = 2: a rewrite plus one corrective pass clears the flags, and a third pass costs a full regeneration while rarely finding more. Report the count ("converged in 2 passes").

04How a pass runs

The default rewrite cycle, in order. Detect mode stops after step 1–2; edit mode swaps the "return text" steps for in-place edits on a file.

1

Audit detect + rewrite

Read the draft and identify every AI-ism, quoting the exact offending text. Auto-detect the context profile if none was given (short + hashtags = linkedin, code blocks = technical-blog, salutation + fundraising = investor-email, default = blog).

  • Group flags by severity so a quick pass can take P0 + P1 first. ↓ §08 severity
  • Skip quoted examples, code blocks, and text marked illustrative — the self-reference escape hatch.
2

Rewrite — or just report mode branch

In detect mode, stop here and hand back the flags plus an assessment. In rewrite / edit mode, replace each flagged span: preserve structure, intent, and every specific technical detail; change only what the rules require.

  • Rewrite toward the five tone principles: vary sentence length, be concrete, have a voice, cut the neutrality, earn the emphasis. ↓ §07 examples
3

Diff summary

List the meaningful changes — not every word, the load-bearing edits and why. In edit mode this is a per-span before → after report, not the whole file.

4

Second-pass audit the built-in pass 2

Re-read the rewritten text and catch survivors — recycled transitions, lingering inflation, copula avoidance, filler. Fix them inline and note what changed. If it is clean, say so.

  • Don't over-polish: sanding away every irregularity pushes writing back toward the AI profile. Keep the natural disfluency. ↓ §05 rhythm

05The AI tells — the pattern catalogue

Roughly forty categories, grouped. Each row: the tell, and the fix. The catalogue is the real intelligence of the standard — word swaps alone won't clear a piece if the shapes stay.

Formatting

TellWhat to do
Em dashes (— and --)Replace with commas, periods, parentheses, or two sentences. Target zero; hard max one per 1,000 words. Applies to headings too; catch both the Unicode em dash and the "--" substitute.
Bold overuseOne bolded phrase per major section at most, or none. If it matters enough to bold, restructure the sentence to lead with it.
Emoji in headersRemove entirely. Social posts may use one or two, end-of-line only, never mid-sentence.
Excessive bullet listsConvert to prose unless the content is genuinely list-like (feature comparison, steps, API params).
Title-case headingsUse sentence case for subheadings. Title case only for the piece's main title, if at all.
List-label periodsA short bold label ending in a period, then a gloss (**Intros.** Years of conferences) → use a colon and lowercase the gloss (**Intros:** years of conferences).
Curly quotes (“ ”)A weak paste-from-chat signal, only in plain-text contexts (code comments, commit messages). Corroborating, never conclusive — don't flag curly apostrophes alone.

Sentence structure & inflation

TellWhat to do
"It's not X — it's Y"Rewrite as a direct positive statement. Max one per piece, and only if it serves the argument.
Hollow intensifiersCut genuine, truly, real (as "a real improvement"), to be honest, let's be clear, it's worth noting that. Just state the fact.
Real/actual adjective inflation"Genuine utility", "real tokenomics" — the noun-modifier form implying the rest is fake, without saying so. Drop it and add the specific claim, unless the contrast is actually named ("real revenue, not grants").
Vague endorsementCut "worth reading / a look / your time". Say why it matters instead.
Significance inflation"A watershed moment for the industry" on a routine event. State what happened; if the sentence still works after deleting the inflation clause, delete it.
Hedge-stacked predictions"Could potentially create", "may eventually unlock" — a modal plus a hedge adverb cancels itself. Pick one.
Copula avoidance"Serves as / features / boasts / presents / represents" → default to "is" or "has".
Compulsive rule of threeVary groupings. Max one "adjective, adjective, and adjective" per piece.
False concession"While X is impressive, Y remains a challenge" — balanced-sounding but weighs nothing. Make both halves specific, or pick a side.

Openers, closers & chatbot residue

TellWhat to do
Chatbot artifacts P0"I hope this helps!", "Certainly!", "Great question!", "In this article, we will explore…", "Let's dive in!" — conversational tics, not writing. Remove entirely.
Sycophantic tone"Excellent point!", "You're absolutely right!" — validates the reader. Cut.
"Let's" constructions"Let's explore / take a look / break this down" — false-collaborative filler. Start with the point.
Rhetorical-question openers"But what does this mean for developers?" stalls before the point. If you know the answer, say it.
Formulaic openings"In the rapidly evolving world of…" — lead with the news or insight; context comes second.
Transition phrases"Moreover / Furthermore / Additionally" → restructure so the link is obvious, or use "and", "also".
Generic / future-narrative closers"The future looks bright", "may become one of the most important narratives of the next cycle" — a prediction with no testable content. Pick the falsifiable version or cut.
Social endorsement closers"This one is worth your time:", "thank me later" — the LinkedIn share sign-off. Say what the thing is and who it's for, then drop the CTA.
Infomercial hooks"The catch?", "Plot twist:", "Here's the thing." — fake momentum. Delete the hook, state the thing.
Emotional flatline"What surprised me most", "I was fascinated to discover" — claims an emotion the writing hasn't earned. Show it or cut it.

Fingerprint leaks — near-proof, fix on sight

TellWhat to do
Cutoff disclaimers P0"As of my last update", "I don't have access to real-time data" — model limits leaking into prose. Find the fact or remove the hedge.
Speculative gap-filling"Is believed to have", "likely began his career in" — guesses dressed as statements. Worse than a disclaimer because the reader can't tell known from invented. Cut or source it.
Unfilled placeholders[Your Name] [INSERT SOURCE URL] 2025-XX-XX — boilerplate pasted unedited. Fill with real content or delete the sentence.
Citation-markup leaksTokens like citeturn0search0 or oai_citation — fingerprints, essentially proof of paste-without-cleanup. Strip every token.
AI-tool URL parametersutm_source=chatgpt.com, utm_source=claude.ai — strip the parameter, keep the link if it's meaningful.
Vague attributions P0"Experts believe", "Studies show" with no name. Cite a specific source or state the claim directly.

Rhythm & structure — the #1 detection signal

Detection tools (including Pangram, trained on 28M human documents) weight structural regularity above vocabulary. Fix every Tier-1 word but leave the rhythm metronomic and the text still reads as AI.

TellWhat to do
Sentence-length uniformityIf most sentences are 15–25 words it sounds robotic. Mix 3–8 word punches with 20+ word flows. Fragments work.
Paragraph-length uniformityIf every paragraph is 3–5 sentences, vary deliberately. Some should be one sentence.
Excessive structureMore than 3 headings in under 300 words, or 8+ bullets in under 200, is AI trying to look organized. Merge into prose.
Synonym cycling"developers… engineers… practitioners… builders" for one thing. Repeat the clearest word instead.
Treadmill effectRestating the premise in fresh words. If you could cut 40–60% and lose nothing, cut it.
Paragraph-reshuffle testIf two body paragraphs can swap without breaking the piece, you wrote a list, not an argument. Add a through-line.
Low vocabulary diversityTTR under 0.40 on general prose over 200 words is a second look. Fix by naming specific things, not by thesaurus.
Self-reference escape hatch When writing about these patterns (a tutorial, this page, the skill file itself), quoted examples are exempt. Text in quotes, code blocks, or marked illustrative is never rewritten — only the author's own prose is flagged.
Rewrite from scratch vs patch If a piece has 5+ vocabulary hits across categories, 3+ distinct pattern categories, and uniform sentence/paragraph length, patching won't fix it — the structure itself is AI-generated. State the core point in one sentence and rebuild.

Tier 3 phrases — the boilerplate rule Multi-word filler ("emerging sector", "the intersection of X and Y", "community-driven", "long-term sustainability") is flagged at 2+ uses of the same phrase, plus a cluster rule: 3+ distinct such phrases in one piece is a strong signal even at one use each — that's the shape LLMs take when they vary their own boilerplate.
Technical-blog carve-out In technical writing, terms with real meaning get a pass: robust, comprehensive, seamless, ecosystem, leverage (actual platform leverage), facilitate, streamline. Still flagged: delve, tapestry, beacon, embark, testament to, game-changer, harness.

07Before / after

The fix is always the same shape: drop the flourish, add the specific claim. These are the standard's own worked examples.

❌

AI-generated

the tell, quoted
  • "nestled within the breathtaking foothills, a vibrant hub of innovation"
  • "The intersection of AI and DePIN may become one of the most important narratives of the next market cycle."
  • "That last move is the contrarian one."
  • "This one is worth your time:"
  • "Reward sustainability."
✅

Rewritten

drop the flourish, add the claim
  • "is a town in the Gonder region; has 12 startups"
  • "DePIN compute may exceed AWS spot pricing for embarrassingly parallel workloads by 2027."
  • (cut the label — let the contrast carry it: "splitting the indexes is what makes the hot path cheap")
  • "Sarah's breakdown of why context windows leak — the clearest explanation I've found for anyone debugging RAG pipelines."
  • "rewards funded from $X/mo in fees rather than emissions"
CategoryBefore → after (word level)
Copula avoidanceThe API boasts three endpoints → The API has three endpoints
Hedge-stacked predictioncould potentially unlock new value → unlocks X (pick one word)
Filler windupIt is important to note that latency dropped → Latency dropped
List-label period**Intros.** Years of conferences. → **Intros:** years of conferences and an operator network.
Five principles for the rewrite
  • Vary sentence length — mix short with long; fragments are fine.
  • Be concrete — replace vague claims with numbers, names, dates.
  • Have a voice — first person, stated preferences, real reactions where they fit.
  • Cut the neutrality — if the piece takes a position, take it.
  • Earn the emphasis — don't call a thing interesting; make it interesting.

Voice profiles (casual / professional / technical / warm / blunt) are the second, independent dial — they set how the prose sounds, not how strict the audit is. If the writer gives a sample of their own writing, match its sentence-length, contraction rate, and word choice instead of a named profile; don't "upgrade" their vocabulary.

Where this sits in the bigger machine In the content machine this is the final pass before publish, after the SEO / AEO / GEO standard. The ship checklist requires it explicitly: "Overall score ≥ 80 · no P0 failures · avoid-ai-writing final pass run." The human-writing gate is as hard as the source-integrity gate — an article that clears SEO / AEO / GEO but fails this pass is not ready.
