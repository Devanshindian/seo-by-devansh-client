How gap-check makes sure the research covers what matters

By this point we have two research documents for a topic: a brief (from DataForSEO) that lists what the article must cover, and a dossier (from STORM) full of gathered evidence. Gap-check is the auditor between them: it treats the brief as a checklist, ticks off every item the dossier can already support, and — only for the important misses — orders a few targeted re-searches to fill them. Here is exactly how it works, script by script.

01The one idea

STORM gathers a lot of evidence, but nobody has checked whether it actually covers the specific things this article needs — especially our unique angle. Gap-check is that check: audit the evidence against the brief, and re-search only the important gaps.

📋

1. Read the checklist

Pull every item the brief says the article must cover — keywords, competitor sections, questions, and our angle.

🔍

2. Audit the evidence

For each item, check whether the STORM dossier already has the substance to write it — proven by a real quote.

🎯

3. Re-search the gaps

For the important misses only, write up to 3 sharp STORM queries and run them again — nothing else.

🧾

4. Write the report

One roll-up: what's covered, what was missing, and which re-runs were fired to fill it.

The one rule that governs everything
A re-run only fires for a real, checkable gap. Every gap must name the exact brief item it came from and why the dossier doesn't cover it. No gap → no re-run. It is capped at 2–3 queries, one round only — never a loop. The scarcity is the point: it forces the re-runs onto our angle, not onto trivia.

02The words you need first

Gap-check sits on top of the two earlier engines, so it borrows their vocabulary. Here it is in plain language, once.

Brief — the DataForSEO research doc. The checklist: what the article must cover (keywords, the sections competitors have, the questions people ask, and our distinct angle).
Dossier — STORM's densely-cited research write-up. The evidence we audit against the checklist.
Coverage item — one thing the brief says matters, pulled out as a single checkable unit (a secondary keyword, a competitor section, a question, the gap we can own).
Verdict — the judge's call on one item: covered, partial, or no — plus a one-line reason and a real quote from the dossier as proof.
Gap we can own — the brief's most important item: our unique angle, the thing competitors don't do. Gap-check cares most about whether the dossier can support this.
Iteration — a fresh, targeted STORM re-run saved as its own folder (iteration-1, -2…). It never overwrites the original dossier.
Headless LLM (Claude or Codex) — a coding assistant run from the command line so a script can call it, no chat window, no API key. Either the Claude CLI (default) or the Codex CLI, set by one --provider switch. All the judging runs on it for free.

Almost all of gap-check is free thinking on a headless LLM CLI (Claude or Codex). The only step that reaches outside is the re-run — because re-running STORM needs STORM.

04The full pipeline — steps 0 to 4

One command runs the whole chain. Each step writes a named file the next step reads. Steps 0–2 and 4 are free; Step 3 only costs money if it actually fires re-runs (STORM's web search). Sections 05–08 zoom in.

What it does: an AI reads the whole brief and pulls out every item the article must cover, plus the asset title and angle. Reading by meaning, so an off-template brief still parses.

  • parse_brief.py → coverage-items.json — each item as {id, type, item, context}.

Judge coverage, item by item free

  • judge.py → coverage-verdicts.json — per item: {verdict, reason, evidence}.

What it does: an AI looks only at the no + partial items, drops the minor or duplicate ones, prioritises (our angle first), and clusters the survivors into at most 3 research questions. Nothing important missing → zero queries.

  • triage.py → gap-queries.json — {queries: [{query, fills, why}]}.

What it does: for each query it runs STORM again and saves the fresh run as its own iteration folder, next to the original — which is never touched. Starts STORM's bridge first if it's down.

Write the report free

What it does: assemble one readable roll-up — the coverage table, the gaps found, the queries fired and where each was saved, and a pointer to every proof file. Pure assembly, no new thinking.

Bounded, not a loop
It's one gap-fill round — after the re-runs, it does not re-check and re-fire. The gap iterations are kept as separate folders (never merged into the original), and the whole thing is resumable, so a crash mid-run resumes instead of repeating the expensive STORM calls.

05What we check — and what we deliberately don't

Not everything in the brief is about evidence. Gap-check only judges items where the question is "does the dossier have the substance to write this?" — and skips pure positioning signals. The policy lives in one place (config.py).

Item typeWhere it comes from in the briefJudged?
gap_we_ownWhat the winners cover → "Gaps we can own"yes — the priority
secondary_kwKeywords → Secondary tableyes
in_bodyKeywords → In-body-onlyyes
winner_h2What the winners cover → Common H2syes
paaSERP snapshot → People-also-ask (on-angle)yes
aio_subtopicSERP snapshot → what the AI Overview coversyes
aeo_faqAI answer landscapeyes — only if there's a usable signal
primaryKeywords → Primaryparsed, never judged
spokes · PAA off-angle · related searches · snippet-holder · "cited by AI"positioning / GEO signals, not dossier substanceexcluded
Why exclude the positioning signals
Things like "who holds the featured snippet" or "is Testlify cited by AI" are about where we rank, not about whether the dossier has enough substance. Judging them would trigger re-runs that can't fix them — so they're left out. primary is read but never judged: the whole dossier is built from it, so it's always covered and never worth a re-run.

06The verdict — how one item is judged

The judge is the smart part. No thresholds, no keyword-matching — an AI reads the actual evidence and decides, and it has to show its work with a real quote.

🎯

One item at a time

Each brief item is judged on its own, with the whole dossier handed over each time — so nothing is missed because it sat in another section.

🚫

Ignore outside knowledge

The judge is told to use only the dossier text, not what the model happens to know. That's what keeps "covered" honest.

📎

Prove it with a quote

A "covered" verdict must carry a verbatim sentence from the dossier. No quote, no coverage.

What the verdicts look like (illustrative)

VerdictTypeItemWhyProof quote from the dossier
coveredsecondary_kw time to hire benchmark Dossier gives industry figures with a source. "Median time-to-hire sits around 44 days across industries…"
partialwinner_h2 how to calculate cost per hire Formula is stated, but no worked example. "Cost per hire equals total recruiting costs divided by the number of hires."
nogap_we_own benchmarks by role and company size + a how-to-improve playbook Only aggregate numbers; nothing segmented by role/size. — (no dossier sentence supports it)
Read the last row
That no on our gap_we_own — our whole angle — is exactly the kind of miss the next step spends a re-run on. A partial can be enough to leave alone; a no on the angle almost never is.

07Spending the 2–3 re-runs

There are only ever 2–3 re-runs to spend, so triage is about ruthless prioritisation: put the scarce re-searches on the misses that actually matter, and ignore the rest.

The priority order (top gets a re-run first)

  1. Gaps we can own — our unique angle. Always first.
  2. Section-anchoring keywords — a secondary keyword that a whole section depends on.
  3. Table-stakes competitor sections — the common H2s a reader expects.
  4. Answer-level items — individual questions (PAA, FAQ candidates).

Triage drops minor and duplicate misses, then clusters the survivors into at most 3 comprehensive research questions — one good query can fill several related gaps. If nothing important is missing, it writes zero queries and no re-run happens.

🎯

Scarcity is a feature

Capping at 2–3 forces the re-runs onto the angle, not onto trivia. An open budget would chase every tiny miss and dilute the research.

🗂️

Kept separate, never merged

Each re-run lands in its own iteration-n/ folder beside the original dossier. The original is never overwritten, so the added evidence is additive and traceable.

One round, then stop
After the re-runs there is no second check — gap-check does not loop. STORM's bridge is auto-started if it isn't running, each fresh run takes a few minutes, and the run is resumable so a completed iteration is never fired twice.

Where gap-check sits in the bigger machine
Gap-check is the coverage gate between STORM and the blueprint. The next engine (research-structure) turns the research into the article's structure — and it ingests the original dossier plus these gap iterations. So gap-check's job is to make sure our angle is actually backed by evidence before the blueprint gets built on top of it.
