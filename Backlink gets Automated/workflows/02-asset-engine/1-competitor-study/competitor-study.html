Asset Engine · Idea Backlog · Method 1 of 3

Competitor Study — steal the format, not the topic

Find the pages that earn competitors the most backlinks. Take the format — the shape that earned those links — and build our own version on a subject we own.

Concept Output A — Competitors B–E — The loop F — Aggregate G — Ideas H — Deliver

01Format, not topic

The format is the shape of the page — a calculator, a glossary, a data report. The topic is what it's about. Backlinks attach to formats. We steal the shape, change the subject.

Topic — what the page covers

Ignore this

A competitor's "Retention Bonus: What It Is and How It Works." Copying the topic means competing head-to-head on their turf.

Format — the shape that earned the links

Steal this

That same page is a definitional answer-bait page. Build one on a term we own.

Method 1 of 3 Competitor Study, Model Other Niches, and Study Trends all feed the same idea backlog. This method finds which formats earn links inside our niche. The other two add formats from outside it.

02What this produces

Two files. The decision file is what the team acts on. The evidence file is what backs it up.

competitor-study-ideas.xlsx — decision file

Tab 1: Format summary — which shapes earn links, ranked by total linking domains across all 15 competitors.
Tab 2: Ideas — one row per buildable asset: brand fit, distinct angle, domain evidence, beatability, effort.

competitor-formats.xlsx — evidence file

One row per kept competitor page across all 15: format tag, full scraped page text, and the Idea # linking it back to Tab 2.

Raw exports and working files go in _raw/ and _work/. The output folder holds only the two deliverables, competitors.md, and brand-scope.md.

Build the list from three sources. Gate on user approval before studying anyone.

  • Direct — same product, same buyer
  • Adjacent content leaders — same audience, different product (ATS platforms, HR academies, industry authorities). If the Semrush lists have none, add them manually.
4

User approval — gate

Present the 15 with the split. Only continue once approved. Write to output/competitors.md.

B–EThe loop — repeat for each of the 15

Steps B, C, D, E run for every competitor and append to one growing master sheet _work/competitor-formats.csv. Move to F only after all 15 are done.

B — Pull Indexed Pages from Semrush (user runs this)

Semrush → search the competitor domain → Link Building → Backlinks → Indexed Pages tab → sort by Domains descending → Export CSV. This is the competitor's own pages ranked by how many sites link to them. Attach in chat; the agent files it to _raw/[competitor]-indexed-pages.csv.

Validate before using: the first row must be the real CSV header. A file starting with <!DOCTYPE html> or a few KB is a login wall, not data — re-export. Tick off each competitor as a valid file arrives.

C — Filter to replicable pages (top 300 by domains)

Take the top 300 rows by Domains. Drop:

  • Homepages and root variants
  • Dead pages — 404 and 410 only. Keep redirects (301/302) on real content paths — many sites serve editorial on migrated URLs and those pages still hold their links. Only drop root-variant redirects.
  • Locale duplicates — /fr/, /de/, /es/ etc. Keep the English original.
  • Commercial and utility pages — pricing, login, signup, contact
  • Navigation and archive pages — /blog/ index, tag/category archives
  • User-generated pages — certificate pages, single question pages, filtered question lists
  • Job postings and app pages
  • Non-content subdomains — keep only root, www., blog., resources.

Keep free tests, tools, and calculators — they earn real links and are replicable. Only commercial product pages get dropped. If one competitor's kept count looks very low compared to the others, the filter is over-dropping — check the redirect rule.

D — Tag each kept page by format

Read the URL and title, assign one format tag. Standard formats: answer-bait (what-is/how-it-works), glossary, calculator, data report, free test/assessment, interview-questions listicle, templates, comparison list, ultimate guide, checklist. Name a new format if a page genuinely fits none — apply it consistently across all 15.

Append to the master sheet: Competitor | URL | Format | Domains | Backlinks.

E — Read every kept page in full

For every kept page, scrape the complete body text and store it verbatim in the "What it is" column. Not a summary, not the title — the full page content. This is what the ideation step reads to find what's missing or thin. If this column just has a title, it's impossible to write a real angle from it.

  • Read every kept page — not just the ones with the most linking domains. Under-served formats tend to show up in the pages further down the list, not at the top.
  • If a page won't load, note it clearly as failed. Never use the page title as a stand-in for the body text — it looks like data but tells you nothing about what's actually on the page.
  • At the end, confirm the count: pages successfully read plus pages that failed should equal the total number of kept pages. If the numbers don't add up, something was skipped.

Once the B–E loop is done, aggregate the master sheet by format and rank by Total Domains.

GTurn every row into an idea

Each kept page becomes one proposed asset: same winning format, subject we own, built to beat the specific gap on that page. Pages that produce the same idea get merged. A 1,500–2,500 row master typically yields 100–300+ ideas.

Three traps this step is designed against

1

Too generic

"Build a glossary because glossaries pull links." No topic, no angle.

2

Too copying

"Build a retention-bonus glossary because Competitor A has one." Head-to-head on their exact topic.

3

Fake analysis

A spreadsheet that looks full but is one template filled 400 times. Tell: asset names read as "Format on Topic," angle gaps repeat the same sentence across rows.

G0 — Distil the brand scope (gate, runs once)

Read the brand brain and write a short output/brand-scope.md: what the company is, subjects it credibly owns, and what's off-limits. This is the shared reference every ideation agent in G2 reasons against. Get user approval before running G2.

G1 — Prepare the working sheet

Assign a stable Row ID to every master row. Add empty columns: Idea # | Asset | Brand fit | Angle gap | Distinct angle | Notes. G2 fills everything except Idea #. G3 fills Idea #.

G2 — Per-row reasoning (parallel sub-agents, 5 rows at a time)

Run as parallel sub-agents sharded by format. Each agent processes its rows 5 at a time — more than that causes the model to pattern-match across the batch and go generic. Each agent receives the approved brand-scope.md, the naming rules, and its rows with full page text from Step E.

For each row, the agent:

  • Sets Brand fit — CORE (own it outright), TRANSPLANT (off-brand subject but proven format — point it at our world), ADJACENT (same buyer, broader subject), or SKIP
  • Writes the Angle gap first — what's thin, missing, paywalled, or stale on this specific page. Must cite a concrete fact from the page.
  • Writes the Asset — a real working title built to fix that gap. Not "Format on Topic" glued together.
  • Writes the Distinct angle — one line on how our version beats this page, drawn from the gap.

After agents return, stitch chunks back by Row ID. Every kept row must appear exactly once. Re-dispatch any agent that dropped rows before moving to G3.

G3 — Merge into distinct ideas

By the end of G2, hundreds of rows each have a freely-written asset name. Many of these are different phrasings of the same underlying idea — one agent wrote "Python Skills Test" while another wrote "Coding Assessment (Python)." They're the same idea. You can't find and merge these by looking for identical text, because the wording is different. The only way to do it reliably is to have a model read all the proposed assets at once and group them by judgment — the same way a human would look across a list and say "these four are all basically the same thing." The result is a clean list of distinct ideas, each with the evidence from all its backing rows combined.

G4 — Score each idea

Beatability (1–3)

  • 3 — backing pages are thin, stale, or paywalled
  • 2 — winnable with one or two clear differentiators
  • 1 — backing pages are strong and well-resourced

Effort (S / M / L)

  • S — one page, days to a week
  • M — a small hub, a few weeks
  • L — original-data report or full hub, a month or more

G5 — Rank and split NOW vs LATER

Sort by: Brand fit (CORE and TRANSPLANT first) → Total Domains × Beatability → Effort (S first). Mark each idea NOW (ships this quarter, based on team capacity) or LATER (in the backlog).

G6 — Sanity check

  • No generic asset names ("Glossary" without a topic)
  • No idea's subject is a single competitor's exact topic
  • Every NOW idea has ≥3 backing pages from ≥2 competitors
  • No angle gap string repeating across 10+ rows
  • No asset names in "Format on Topic" pattern
What a good idea looks like "Hiring & Assessment Glossary with Bundled Micro-Tests. 47 competitor glossary pages across 8 competitors. Of those: 32 are definition-only, 11 add a worked example, 4 include a template — nobody bundles a test. That's our angle." Real name. Subject we own. Angle built from evidence.
