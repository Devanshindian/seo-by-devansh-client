Asset Engine · Idea Backlog · Method 1 of 3

Competitor Study — steal the format, not the topic

Find the pages that already earn competitors the most backlinks, copy the format (the shape that earned those links), and build our own version on a subject we own. Fully automated end to end — one command pulls the data, reads every page, and hands back a ranked list of buildable ideas. Here's exactly how it works, script by script.

01The one idea

Backlinks attach to formats, not topics. If a format pulled hundreds of linking domains for a competitor, that shape works in this niche — so we build the same shape on a subject we own, better than theirs. The engine finds which shapes win, then writes one buildable idea per winning page.

🔍

Find the magnets

Pull every competitor's own pages, ranked by how many sites link to them.

🏷️

Tag the shape

Label each page by format — glossary, data report, free test — never by topic.

💡

Write the idea

Same winning format, a subject we own, an angle that beats the specific page.

📊

Rank & ship

Merge duplicates, pool the proof, rank by pooled link-pull, split NOW vs LATER.

The rule that governs everything Format = copy the competitor's own format; never upgrade an idea into a tool. A page's shape is decided once (its Step-D tag) and carried forward untouched. An article we plan to beat stays an article; a data report stays a data report. The win comes from a better angle a writer can deliver from public sources, not from bolting on a calculator or a quiz. (This is the format-honesty fix — see ↓ §05.)
Method 1 of 3 Competitor Study, Model Other Niches, and Study Trends all feed the same idea backlog. This method finds which formats earn links inside our niche; the other two add formats from outside it.

02The words you need first

A few load-bearing terms, defined once. Everything below reuses these exact words.

Format vs topic. The topic is what a page is about (retention bonuses, a Python test). The format is its shape (a "what is X" explainer, an annual data report, a free skills test). We copy the shape, never the exact topic — copying the topic just means competing head-to-head and losing.
Referring domain (follow vs nofollow). A referring domain is one website linking to a page. A follow link passes authority; a nofollow link passes none. The engine ranks pages by follow referring domains only — a page with 340 nofollow links looks like a magnet but passes nothing.
DataForSEO. The paid API that replaced the old manual Semrush exports. Two calls do the whole gather: competitors_domain (who ranks for our keywords) and domain_pages (a competitor's own pages with their backlink profile). Nothing for a human to download.
Brand scope. A short approved doc (brand-scope.md) distilled from the company's brand-voice + features + record: what we are, subjects we can credibly own, and what's off-limits. Every idea-writing agent reasons against it, so 300 parallel passes stay pointed the same way.
Brand fit — CORE / TRANSPLANT / ADJACENT / SKIP. The verdict each page gets against the scope. CORE = a subject we own outright. TRANSPLANT = off-brand subject but a link-pulling format — keep the shape, point it at our world. ADJACENT = same buyer, broader subject. SKIP = outside our world or junk.
tool_escalation. A column that is empty by default. It is filled only for the rare idea whose format genuinely needs a build a writer can't produce (a real scored coding test needs an assessment engine). It flags that idea for a separate build track — it never changes the title, and it is the only place a "build a tool" decision is ever recorded.
Semantic dedup (embedding). Turning each idea's title into meaning-numbers (an embedding) so ideas that mean the same thing sit close together, even when worded differently ("Python Skills Test" vs "Coding Assessment (Python)"). Used in Step G2.5 to find likely duplicates before an LLM judges them.
The master sheet. One row per kept competitor page across all competitors (g2_sheet.json → competitor-formats.xlsx): its format, backlink numbers, full scraped text, and the idea it rolls up into. The evidence file behind every idea.

03The architecture

One orchestrator runs thirteen steps in order. Each step is its own script that writes a named file; the next step reads that file. A crash resumes where it stopped, and a finished company re-runs in seconds because every step is cached by its output.

Shared fileIts job
run_competitor_study.pyThe orchestrator. Pure sequencing — calls each step's script in order, skips a step whose output already exists, stops at the two human gates (A and G0). One command: --company <slug>.
scripts/config.pyEvery path and tunable from one anchor. Company is one setting. Holds the knobs (batch sizes, worker counts, the dedup threshold, credit floor).
_shared/llm.pyThe one AI caller. Runs prompts through the local Claude or Codex CLI — no API key. Returns validated JSON, retries once on a bad parse.
_shared/dfs.pyThe one DataForSEO client. Every paid call goes through here, so the key lives in one place and a pre-flight credit check can gate the whole run.
_shared/voyage.pyThe Voyage embeddings client (Step G2.5). Embeddings are cached per content-signature, so a re-run costs no tokens.
prompts/*.mdOne file per LLM call — shortlist, tag-format, canonicalize, brand-scope, reason-rows, dedup. Diffable, single-sourced, never inline in code.

The other axis is code vs LLM: filtering, aggregating, and the final ranking are pure Python (deterministic, free, reproducible); the judgment calls — which shape a page is, what the gap is, which ideas are the same build — are the LLM's, each behind its own prompt file.

04The full pipeline

Thirteen steps, grouped into phases. Each names its script and the file it writes. Real numbers below are from the Testlify run (labelled real).

Phase 1 · Shortlist the competitors
A

Find & approve ~15 competitors paid gate

One DataForSEO competitors_domain call generates candidates (ranked by keyword overlap — a noisy generator, not the answer), an LLM shortlists ~15 with real product/audience overlap, split into ~10 direct + ~5 adjacent content leaders. A human approves before anyone is studied.

  • step_a_competitors.py · prompt shortlist-competitors.md
  • writes output/competitors.md
Phase 2 · Gather & filter the pages
B

Pull each competitor's link-earning pages paid

One domain_pages call per competitor returns their own pages with each page's backlink profile, ranked by follow referring domains. Cached one file per competitor, so a credit stop never re-pays for a competitor already pulled.

  • step_b_pages.py → _raw/[domain]-pages.json
C

Filter the top 300 to replicable pages code

Take the top 300 by follow domains, canonicalise + dedupe URLs, then drop only the un-buildable: home / root variants, dead pages (404/410 only — redirects on real content paths are kept), locale dupes, commercial/utility pages, nav/archives, non-content subdomains. Free tests, tools and calculators are kept — they're the link magnets.

  • step_c_filter.py → _work/candidates/
  • Matches keywords on the URL path, never the whole URL (the brand-name-in-domain trap). Alarms if any competitor's kept count collapses (the over-drop scar).
Phase 3 · Tag the format
D

Tag each kept page by format LLM · free

The LLM reads the URL + title + headings (the strongest signal) and assigns one format — the shape, not the topic. It only decides the shape; junk is dropped by three other gates, not here. It may name a new format when nothing fits.

  • step_d_format.py · prompt tag-format.md → _work/formats/
F0

Canonicalise the format labels LLM · free

The tagger runs in independent batches, so it names the same shape several ways (measured: 127 labels for ~1,200 pages, six ways to say "product page"). One LLM pass merges the variants into a canonical set, so one strong format doesn't look like three weak ones — the exact question Step F answers.

  • step_f0_canonical.py · prompt canonicalize-formats.md → _work/format-canonical.json
Phase 4 · Read every page
E

Read every kept page in full free

Re-execs into Layer 00's site-catalogue extractor (a 5-rung ladder that keeps the longest result, so JS-heavy pages still yield text) and saves each page's complete clean text into the "What it is" column — verbatim, no character cap. Every kept row, not a top slice. A page that won't load is marked FETCH FAILED, never faked with its title.

  • step_e_read.py → _work/read/ + _work/master.json
  • Prints a tally: N rows → X read, Y failed, and X + Y must equal N.
Phase 5 · Aggregate
F

Aggregate by format across all competitors code

Roll the master up by format, ranked by total follow domains. Formats that recur across several competitors carry the strongest signal. This becomes Tab 1 of the deliverable.

  • step_f_formats.py → output/format-summary.csv
Phase 6 · Turn every page into an idea
G0

Distil & approve the brand scope LLM · free gate

Distil brand-scope.md from brand-voice + features + the company record: what we are, subjects we own, what's off-limits. A human approves it — the one place direction is set; everything downstream reasons against this anchor.

  • step_g0_scope.py · prompt g0-brand-scope.md → output/brand-scope.md
G1

Prepare the working sheet code

Give every master row a stable Row ID, add the empty idea columns, and flag byte-identical bodies as text-dups (so G2 reasons over each unique text once, but their backlink proof is protected).

  • step_g1_sheet.py → _work/g_sheet.json
G2

Per-row reasoning at scale LLM · free

Parallel passes, sharded by format, 5 rows at a time (more and the model pattern-matches across the batch and goes generic). Each pass reads the full page text and writes, per row: brand fit → angle gap → asset title → distinct angle → tool_escalation. The whole creative judgment lives here.

  • step_g2_reason.py · prompt g2-reason-rows.md → _work/g2_sheet.json
  • ↓ §06 — the gap→asset→angle rules
Phase 7 · Dedup & rank
G2.5

Semantic dedup Voyage · cached LLM · free

Embed every idea (Voyage), block each idea's nearest neighbours above a cosine threshold into small candidate clusters, then let the LLM judge each cluster: SAME build, COMBINE into something richer, or keep SEPARATE (the default). It never sees the whole set at once, so it can't squish.

  • step_g25_dedup.py · prompt g-dedup.md → _work/dedup-report.json
  • ↓ §07 — embed → block → adjudicate
G3

Keep the specific ideas, pool proof, rank code

Drop the merged-away rows, group any exact-name twins the threshold missed (deterministic, free), pool each survivor's backlink proof, and rank: brand-fit tier → pooled follow-domains → competitor count. Mark the top N (team capacity) NOW, the rest LATER. No LLM here.

  • step_g3_ideas.py → output/ideas.csv + _work/ideas-ranked.json
Phase 8 · Deliver
H

Build the two clean end-files code

Pure assembly — it invents nothing. Tab 1 (format summary) + Tab 2 (ranked ideas, coloured by brand fit, backing URLs inline) in the decision file; one row per kept page in the master/evidence file.

  • step_h_deliver.py → competitor-study-ideas.xlsx + competitor-formats.xlsx

05Format honesty — stop over-tooling

The most important fix in this engine. The old version turned most ideas into interactive tools — calculators, quizzes — to "beat" the competitor, in a niche where the pages that actually rank are plain articles. Now a page's format is copied once and never upgraded, and the differentiator has to be something a writer can deliver from public sources.

The one rule Format = the Step-D tag, copied. G2 may never upgrade an article into a tool. The shape lives in the Format column and is decided exactly once. The idea wins on its angle, never on a bolted-on tool.

Why over-tooling was wrong — the niche's own numbers real · Testlify

In this niche, tool-shaped pages barely earn links, while article-shaped pages earn nearly all of them. Building tools to "win" was fighting the evidence:

The three supporting rules (all in g2-reason-rows.md)

Differentiator

Writer-deliverable only

The gap must be closable by reading + citing public sources — fuller coverage, depth, examples, structure, or a refreshed public stat. Not "add a tool", "add our own data", or "run new research" — those break an automated writer.

Title

No shape-words

Banned in the title: Calculator, Quiz, Interactive, Dashboard, Generator, Tool, Estimator. The shape lives in the Format column; the title carries subject + angle.

tool_escalation

The rare real build

Empty by default. Filled only when the format itself is a tool (a scored coding test needs an assessment engine). Flags a separate build track — it never rewrites the title.

tool_escalation in the real run Of 1,794 ideas, 164 (~9%) carry a tool_escalation flag — every one a Quiz / assessment idea where matching the competitor genuinely means building a real scored test, e.g. "Format tag is Quiz/assessment — matching it means building a real scored coding test — needs an assessment engine, not an article." The other 91% stay as articles a writer can produce.
Junk is handled elsewhere, on purpose The format tagger only decides the shape. Off-brand and commercial pages are caught by three separate gates: Step C's URL filter, G2's own brand_fit=SKIP (the idea-writer skips a sales/off-brand page), and a final relevance recheck on the merged pool. In the real run, 1,766 master rows were marked SKIP and never became ideas.

06Per-row reasoning — gap → asset → angle

This is where the real intelligence sits. For each competitor page, one small parallel pass does the whole creative judgment in one place, in a fixed order: substance first, the title last.

OrderFieldWhat the pass writes
1Brand fitCORE / TRANSPLANT / ADJACENT / SKIP against the approved scope. Strict — a different product world (reference checks, payroll) is SKIP even if hiring-adjacent.
2Angle gap (first)What THIS specific page is missing, citing a concrete fact from it. Must be a content gap a writer can close — thin coverage, no examples, a stale stat. The gap is what the asset is built to beat.
3AssetA real working title with the differentiator visible, no shape-word, never "[Format] on [Topic]".
4Distinct angleOne line: how ours beats this page, drawn straight from the gap and deliverable from public sources.
5tool_escalationEmpty, unless the format truly needs a build.

The anti-template test runs on every field: "Could I have written this without reading the page?" If yes, rewrite. Below are the prompt's own good/bad examples.

Angle gap — ❌ templatedAngle gap — ✅ usable
"generic explainer — no original data, no inline test""11 questions, MCQ only, no public sample, free PDF cert"
"thin editorial list — generic items""350-word definition, no template, no example screenshots"
"round-up that rarely updates""2022 salary data, last refresh 14 months ago"
Their gap❌ template-fill title✅ real title (subject + angle, no shape-word)
350-word definition, no examples, cites a 2022 stat"Glossary on hiring terms""The Hiring & Assessment Terms People Actually Get Wrong (with worked examples)"
benchmark cites 2022 data, no role breakdown"Skills-Hiring Report Calculator""What Skills-Based Hiring Really Looks Like in 2026, Role by Role"
Why 5 rows, not 50 Handed a big block, the model stops reading each page and writes one description that "fits them all" — the fake-analysis trap (400 rows that are really 8 templates). Five rows keeps its attention on each page. About 1,500 rows becomes ~300 tiny parallel passes on a fast mid-tier model (Sonnet); the strong model is saved for later judgment.

07Semantic dedup — keep the specifics, merge only true twins

An earlier build merged the ~2,100 grounded ideas down into ~112 broad categories. A blind quality eval killed it: grounded ideas scored 4.6, the old hand-run 4.4, the squished categories only 3.4 — the hard merge wrecked the specificity. The fix keeps every specific idea and merges only genuine repeats, using the textbook entity-resolution pattern.

1 · Embed

Meaning-numbers

Embed each idea's build identity (asset — format, not the whole angle) with Voyage, so genuine twins sit close. Cached per signature — re-runs cost no tokens.

2 · Block

Propose candidates

For each idea, union its nearest neighbours above a cosine threshold (0.80) into small clusters. The embedding only proposes — a glossary and a test library can sit at 0.75, so it never merges alone.

3 · Adjudicate

The LLM judges

Hand each small cluster to the LLM: SAME (delete dupes, pool proof), COMBINE (write one richer asset — the only text it may write), or SEPARATE (the default). Never the whole set at once.

The default is keep When unsure, the adjudicator keeps ideas SEPARATE. Several competitors landing on one idea is validation, not noise — those merge into one idea that carries all their pooled backlink proof, a stronger signal, never a weaker one.
