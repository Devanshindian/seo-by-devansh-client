01The one idea

Reddit is where a niche argues out loud. Method 3 reads that argument, distils it into recurring tensions, keeps only the ones a writer would cite, and shapes each into a link-worthy asset.

🧵

Scrape the argument

Pull the top posts of the year from approved subreddits — body, image text, and top comment threads.

🔍

Distil into tensions

Tag each post with phrases, then cluster those phrases by meaning into one-sentence shared pains.

🚦

Filter to the linkable

Score each tension on Linkability and Ownability. Pure drama dies here; only citable, ownable pains survive.

💡

Shape into ideas

Each kept tension becomes one asset idea whose shape comes from the tension itself, not a borrowed format.

The one rule that governs everything

Reddit measures attention, not linkability. The loud posts are usually viral drama nobody would ever cite. The entire value of this method is the filtering — keep only tensions that are timely and something a writer would reference an asset about.

Method 3 of 3

Methods 1 and 2 surface proven winners and proven formats. Method 3 adds the one thing they can't: timeliness — angles that only exist because people are arguing about them this month. All three pools stay separate and merge at the end of the idea-backlog stage.

02The words you need first

A few terms carry the whole method. Each is defined once here, then used exactly.

Tension — one sentence stating a specific shared pain (who is frustrated with what), never a topic label. "Fake remote jobs" is a topic; "candidates apply for roles listed as remote that turn out to be secretly onsite" is a tension. The tension is the only unit this method works in.
Phrase — a tight 2–4 word snippet pulled from a post that captures what it is about ("fake remote listings", "ghosted after interview"). Single words are noise; phrases are the raw material that cluster into tensions.
Content card — one post rendered as a compact block for the model to read: id + subreddit + score/comments + title + body + OCR'd image text + top comments. The _posts.py helper builds these, and one place reads the scrape.
Embedding — a phrase turned into "meaning-numbers" (a vector) so two phrases that mean the same thing sit close together even when the words differ. Method 3 clusters phrases by embedding because recurrence lives at the level of meaning, not exact spelling.
Linkability — would anyone actually cite an asset about this tension? Scored on four yes/no questions (a citable number · a journalist would reference it · evergreen · fits a proven link-bait format). Needs ≥3 of 4.
Ownability — can this company credibly own the tension? Judged against brand-scope.md as CORE, TRANSPLANT, ADJACENT, or out-of-scope.
Transplant — an out-of-scope tension is not dropped on sight. First check: can the same linkable shape be pointed at an in-scope subject? If yes, keep it as a TRANSPLANT rather than binning it.
Implied data point — the number a tension is begging for: the stat that would settle the debate or prove its scale ("what % of 'remote' listings are actually onsite?"). This is usually what the asset ends up being.
misc — the bucket for a post that shares no pain with any tension. It is not a dumping ground for off-brand-but-coherent posts (those still get a real tension). The verify gate fails the run if misc exceeds 15% of posts.

03The architecture — two phases, one scripted

The method splits at the one place a human is needed. Phase A gathers the data behind a human gate; Phase B mines it into ideas as one unattended, resumable command.

🧑‍💻

Phase A — Gather

A separate tool, with the one human gate

Discover subreddits, vet each by real post activity (not subscriber counts), get the user to sign off, then scrape. Choosing the communities is a judgment call, so it stays a human step.

Runs as
scripts/reddit/reddit-scrape.py — our own scraper. Free. Human approves the subreddit set.
⚙️

Phase B — Mine

The scripted pipeline — no gates

Everything from raw scrape to final ideas runs as one resumable command: stages 2a → 4, then a fail-closed verify gate. The filter (KEEP/DROP) runs automatically, like Methods 1 and 2 — no human stop mid-run.

Runs as
run_study_trends.py --company <slug> — pure sequencing; a stage whose output file exists is skipped unless --redo.

Almost every stage is a code shell around one LLM judgment (Claude or Codex), with the counts done mechanically. The prompts live in prompts/, one file per call, never inline. The one exception is 2b, which adds an embeddings pass (Voyage) to cluster phrases before the model names them.

2a

Read each post as a content card and pull the 2–3 phrases that best capture it — the OP's core complaint, plus any point several different commenters land on. Embarrassingly parallel: posts are sharded and run at once.

2c

Assign every post to a tension free · LLM

Send each post back to the model with the tension list and ask which one its dominant pain belongs to. One primary tension per post; a post that shares no pain with any tension goes to misc.

  • step_2c_assign.py · prompt 2c-assign.md → _work/post-tension-map.tsv

2d

For each tension the model writes the judgment fields (core pain, audience, emotion, best example, representative quotes, sub-questions, implied data point); the engagement numbers are summed mechanically off the Posts tab. Verdict columns are left blank for stage 3.

05Phrases → tensions (stage 2b, the real intelligence)

This is where the method lives or dies. Get the grouping wrong and everything downstream inherits a bad sort. A tension is one sentence stating a specific conflict — not a topic label.

Topic label — vague

"Fake remote jobs"

→
Tension — specific and buildable

"Candidates apply for roles listed as remote that turn out to be secretly onsite, or quietly revert to office later."

Why cluster by meaning, not by words

On the real Testlify run the 425 posts produced 1,224 distinct phrases but only 18 that repeat verbatim. Recurrence lives in meaning, not exact spelling — "fake remote listings", "secretly onsite", and "remote then RTO" are one pain in three wordings. And 1,224 phrases won't fit one grouping call. So 2b does it in four moves:

  1. Embed every distinct phrase with Voyage (cached to _work/phrase-emb-*.npy so a re-run is free).
  2. Cluster the vectors into a controlled number of groups — KMeans at TARGET_CLUSTERS (45). A threshold merge made one 584-phrase mega-blob on this dense space, so the count is fixed instead.
  3. Name each cluster with a parallel LLM call that states the one shared-pain sentence — and splits the cluster into two if it really holds two pains. This naming call is the merge-check; its record is written to merge-check.md.
  4. Dedup the resulting tension sentences: merge only near-identical ones (cosine ≥ MERGE_SIM 0.85 — the same pain named by two clusters), keeping every genuinely distinct pain. Fragments with fewer than 2 phrases are dropped to misc.
Keep specific — don't force a target count

The naming step deliberately over-produces candidate tensions, and dedup merges only true duplicates. Squishing distinct pains into a round number is exactly the failure this avoids — the real cut is stage 3's brand-scope filter, not the clustering.

Same topic, different pain — why they stay separate

Two phrases can look related on the surface and be completely different tensions. "Ghosted after interview" and "endless interview rounds" are both interview complaints — but one pain is silence and disrespect, the other is process length. Merging them under "interviews" would blur what the asset has to say, so the naming call splits them.

06The filter (stage 3)

Two explicit tests per tension, both LLM judgments but structured ones. This is the gate the one rule points at — where pure drama with no citable substance dies.

Test A — Linkability

Would anyone cite an asset about this? Four yes/no questions:

  • Is there a citable number an asset could produce?
  • Would a journalist or blogger reference it?
  • Is it evergreen, not a one-off viral moment?
  • Does it fit a proven link-bait format (index / calculator / data report / guide)?

Needs ≥3 of 4 (LINKABILITY_MIN).

Test B — Ownability

Can this company credibly own it? Judged against brand-scope.md — the same anchor Methods 1 and 2 use:

  • Does it sit inside scope: CORE / TRANSPLANT / ADJACENT?
  • Does the company hold the data, product, or authority?
  • Out of scope → run the transplant check before dropping.

CORE or TRANSPLANT passes; ADJACENT is a MAYBE.

The transplant check is mandatory

An out-of-scope tension is never binned on ownability alone. First ask: is there a strong linkable shape here we can point at an in-scope subject? The verdict is recorded for every out-of-scope tension — even when it's "no transplant, drop" — so the audit shows the check happened.

07Tension → asset idea (stage 4)

One kept tension becomes one asset idea. No format-borrowing here — that's Methods 1 and 2's job. Method 3's edge is the tension itself, so the asset's shape comes straight from what the tension is calling for.

The idea prompt gets the tension's full evidence (sentence, core pain, all the phrases, quotes, audience, emotion, implied data point, sub-questions, Reddit signals), the brand-fit verdict from stage 3, and the brand brain — brand-voice.md + features.md + stats.md. It returns a real working title with the tension visible in it, plus the unfair advantage — the nameable product, data, or authority that lets this company own it.

The verify gate — seven fail-closed checks

Self-attestation failed once before (a checklist the agent claimed it ticked, a merge-check written after the tensions to look done). So the final check is a script, not the agent's word. It exits non-zero if any of these fail:

CheckWhat it enforces
ORDERmerge-check.md must predate tensions.csv — the gate ran first, not after the fact.
COVERAGEevery scraped post assigned exactly once; misc ≤ 15%.
OFF-BRANDno DROP bucket over 8 posts unless it's examined by name in merge-check.md (kills the junk drawer).
SIZE-ALARMany kept tension with more than 15 phrases must be justified by name in merge-check.md.
GATEevery kept tension appears in merge-check.md — formed through the gate, not bolted on.
PRODUCT-LEAKkept tensions' sub-questions contain no solution/product words (no stage-4 bleed-back).
IDEASkept-tension count == idea count.
Where this sits in the bigger machine

Study Trends is Method 3 of the asset engine's idea backlog. It reads brand-scope.md (from Method 1's competitor study) as its ownability anchor and the brand brain for voice. Its study-trends-ideas.csv is a separate pool from Methods 1 and 2; all three merge at the end of the idea-backlog stage, then get prioritised. Method 3's unique contribution to that merge is the timely, current-events tension no other method can surface.
