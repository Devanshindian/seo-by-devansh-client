Reuse Check — do we already have this asset?

Before building anything, every idea in the merged pool is checked against existing content. RAG finds the closest pages; an LLM reads them and decides what to do.

01Why this runs before building

Two payoffs: don't rebuild something we already own, and don't research from scratch when related pages can be reused.

We use a two-step process: first, a semantic search finds the existing pages most likely to be relevant to each idea — ranking them by meaning, not just keyword overlap. Then an AI agent actually reads those pages and makes the judgment call. The search step can only say "these look similar." It can't decide whether to rebuild, improve, or start fresh — that requires reading and thinking, which is the agent's job.

Inputs clubbed-ideas.csv — the merged pool from all three methods, with the reuse columns empty.
content-database.csv — must include the Full content column. Every existing page is indexed from this file.

03The three stages

1

Build the search index — once per company

Every page in the content database is turned into a searchable index. Each page is indexed in two ways: once from its title alone, and once from its full body text. The reason for splitting them is that a long article body can overwhelm the title signal — indexing the title separately ensures a page about "hiring metrics" is always findable even if the body covers dozens of other topics. This index is built once and only needs to be refreshed when the content database changes.

2

Find the top 15 closest pages per idea

For each idea, we search the index using the asset title as the query. The distinct angle is deliberately left out — it contains competitor and gap language that would steer the search in the wrong direction. The search casts a wide net of 40 candidates, then a second pass re-reads those 40 more carefully and cuts it down to the 15 most genuinely relevant. Alongside this, a simple keyword scan finds every existing page whose title or URL contains the asset's topic term — this gives a complete, no-omissions list of everything we own on that topic. Both sets of links are written into the CSV.

3

LLM judges each idea — one agent per idea, in parallel

Each sub-agent receives the asset title, its distinct angle and format, plus the full text of its top candidate pages fetched on demand. It runs three tests on each candidate — topic match, format match, angle match — then returns one verdict, the relevant links, and a short explanation. No similarity scores are shown to the agent; the verdict comes purely from reading.

04The four verdicts

Applied top-down — first match wins.

🟢

Already have it

A page that already delivers this asset — same topic, same format, and already has the distinct angle at good quality. Building again would duplicate. Rare — the angle is usually new.

🟡

Improve existing

One page is clearly the same topic but weaker — missing the angle, wrong format, thin, or outdated. Building means upgrading that page, not creating a second one. Example: asset is a cost calculator; we have a 700-word text article on the same topic. Upgrade it.

🟠

Build from parts

No single page is this asset, but two or more candidates each hold reusable material — data, definitions, sections — worth pulling from. Build new, reuse the research.

🔴

Brand new

Nothing relevant. No candidate genuinely covers the topic or feeds the build. Start from scratch.

05Review output

The finished CSV is delivered in two forms for review — always both, not just the raw file.

  • A self-contained HTML viewer — one offline file with all ideas inline, filterable by source method, brand fit, verdict, and format. Each row expands to show the full reasoning and all links clickable. Reviewers can mark Keep / Maybe / Cut per idea and export their decisions.
  • A GitHub Pages link — the same HTML published so a reviewer opens one URL with nothing to install. Hosted on a personal account with a randomised repo name. When the review window closes, the repo comes down.
Always update in place Once the link is shared, every re-run pushes to the same repo and URL — never create a second one. The shared link must stay live and consistent through the review period.
